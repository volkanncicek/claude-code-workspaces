# Security

## Reporting a vulnerability

Report privately through GitHub: **[Security → Report a vulnerability](https://github.com/volkanncicek/claude-code-workspaces/security/advisories/new)**. Please do not open a public issue for a security problem.

This is a small single-maintainer project. Expect an acknowledgement within a week, and a fix released as a new version on PyPI once the problem is confirmed. If it is not a `ccw` bug but a Claude Code one, report it to Anthropic instead and let me know so I can document the interaction here.

## What the tool touches

None of this is a vulnerability by itself, but it is what an audit would want stated plainly.

- **It reads conversation content.** `ccw` parses the JSONL transcripts under `~/.claude/projects/`, which contain your Claude Code conversations in full — prompts, model replies, tool calls, file contents and whatever else was said. That is where the session labels, titles and search text in the list come from. All of it stays on your machine: `ccw` makes no network requests of any kind and sends nothing anywhere.
- **It strips control characters out of anything it displays.** A conversation title, a first prompt or a branch name is text you or a model wrote, and it ends up rendered in a terminal. Rich and Textual pass an ESC byte through to the screen, so an escape sequence that reached a title would be interpreted rather than shown. Every string the transcript parser hands onward therefore has the Unicode `Cc` category removed first, with tabs and newlines folded to a space; the working directory is deliberately left alone, because it is a real path the launcher must not rewrite, and no legitimate path component can contain those characters anyway.
- **It reads `~/.claude.json`.** Only to answer whether a working directory's repository root has already had its trust dialog accepted, so the restore checklist can warn you before opening panes that will stop for a prompt. The file also holds unrelated Claude Code state, including credentials in some configurations; `ccw` does not read those keys and never writes the file.
- **It only ever writes under `~/.ccw/`, and some of what it writes there is conversation content.** Workspaces, snapshots, keep and archive marks and the trash directory all live there, keyed by session id — and so do two caches: `roots.json`, which remembers which repository root a working directory resolves to, and `heads.json`, which holds each session's AI-generated title and the user's literal first message. So `~/.ccw/` is not free of prompt text, and anyone who backs it up, syncs it or shares it is moving that content with it. The cache is kept rather than dropped because rebuilding it means reading every transcript on disk again, which is the slowest thing the tool does. Nothing under `~/.claude/` is written, moved or deleted, so `ccw` cannot corrupt or lose a conversation, and deletes of `ccw`'s own files go to `~/.ccw/trash/` and are confirmed first.
- **It runs `claude` and `git` to read state, on every run.** Each launch, and each refresh while the session list holds focus, runs `claude agents --json` (`live.live_sessions`, every `tui.POLL_SECONDS`, five seconds). Resolving a session's repository root runs `git -C <cwd> rev-parse --show-toplevel` (`repos.git_root`) in every distinct working directory recorded in the transcripts, including projects you stopped working on long ago. Both are read-only queries, and both are handed paths that came out of your own transcripts.
- **It spawns terminal processes.** Restoring a workspace launches `wt` with one pane per session, each pane being `pwsh -NoExit -NoLogo -NoProfile -EncodedCommand <base64>` (`WindowsTerminalLauncher.build`). The encoded script is built by `_pane_script`: it removes every `CLAUDE_*` variable from the pane's environment, sets `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE=1`, changes to the working directory recorded for that session, then runs `claude --resume <session-id>` — plus `--fork-session` when you asked to fork. The directory change is terminating, so a session whose directory has since been deleted or renamed stops the pane at a prompt instead of resuming that conversation somewhere else. `-EncodedCommand` takes base64-encoded UTF-16LE, which is simply what the parameter accepts; it is the documented way to pass a multi-line script through a command line, not obfuscation, and the decoded text is the four lines just described. Session ids and working directories therefore reach a command line, so a workspace file is as trusted as the machine it came from: do not restore a `~/.ccw/` directory you did not create yourself.
- **`claude` is resolved to an absolute path** before launching, because panes started by Windows Terminal get the system `PATH` rather than the current shell's.

## Scope

Anything that lets `ccw` write outside `~/.ccw/`, execute a command that did not come from a session record, leak transcript content off the machine, or expose credentials from `~/.claude.json` is in scope. Claude Code's own behaviour, and the contents of your transcripts, are not.
